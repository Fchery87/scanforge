## Evidence behind the choices

The inspected baseline supports these decisions but does not implement them:

- [Completion schema](../apps/api/app/schemas/scan_completion.py) has no contract version, attempt, or aggregate limits. Only scanner name currently has a length bound.
- [Completion service](../apps/api/app/services/scan_completion.py) locks Scan and rolls back exceptions, but accepts caller summary, does not fence attempts, and reconstructs replay counts from the retry. Preserve the transaction boundary, replace its authority rules.
- [Finding lifecycle](../apps/api/app/services/finding_lifecycle.py) accepts every known target and uses primary-scanner completion plus threshold two. [Finding persistence](../apps/api/app/services/findings.py) increments a repository-wide counter and reopens fixed rows without ordered/ref evidence. Two remains the intended threshold; delivery counting does not.
- [Internal routes](../apps/api/app/api/v1/routes/internal.py) expose standalone findings, scanner-run creation/update, status, and upload authority. Fencing only `/complete` would leave bypasses. Disable those authoritative legacy writes during coordinated cutover.
- [Finding routes](../apps/api/app/api/v1/routes/findings.py) permit owner/admin/security_reviewer. [RBAC](RBAC.md) names all five roles. Retain the current reviewer group rather than inventing a risk-approver role, but move authorization into the service boundary too.
- [Repository model](../apps/api/app/db/models/repository.py) has nullable external_repo_id and display-name uniqueness, not a ref-generation model. [Scan model](../apps/api/app/db/models/scan.py) has branch_name and commit_sha but no ancestry, receipt, attempt, or independent scanner outcome. Extend these records rather than presume these fields already exist.
- [Queue client](../apps/worker/app/clients/queue.py) reclaims at 30-minute idle and has no API attempt authority. It treats some HTTP failures as an empty poll. [Orchestrator](../apps/worker/app/services/scan_orchestrator.py) acknowledges a local canceled observation before final workspace cleanup and may route post-completion errors into failed status. These are R09 implementation gaps, not accepted semantics.
- [Worker persistence](../apps/worker/app/services/scan_pipeline/persistence.py) reports only completed/failed runs and unversioned summaries. API and workers require a coordinated contract cutover.
- [Deployment configuration](../render.yaml) names a starter API plan and two web workers, but contains no measured completion RSS or representative beta finding-size distribution. It cannot settle G1. The readiness plan's 10,000-finding performance fixture informs a candidate count, not approval of a 16 MiB envelope.

## Review clarifications

Branch retirement creates a new baseline generation; it never counts as absence. Presence resets counters only on the same tracked branch generation, using commit ancestry order; presence on another branch is retained separately and cannot erase this branch's obligation. Failed or missing evidence projects as operational completion with `partial` scanner completeness and `ineligible` lifecycle eligibility, never as clean or canceled. Replay requires the winning principal or an enabled replacement with explicit receipt-read capability; disabled principals cannot read or replay. Legacy scanner-run/findings routes return 410 at cutover, and direct service calls enforce the same attempt and terminal checks.

Future database timestamps require trusted source metadata and must be within five minutes of API time; missing source, unverifiable provenance, or future drift is unknown and ineligible.

G1 measurement records must include fixture IDs and sanitized size/count distributions, host class and memory, concurrency, RSS peak, transaction p95, rollback result, scanner duration, queue visibility, test SHA, and operator approval or amendment.

## What remains unresolved

G1 is the unresolved payload approval gate. Lease, renewal, reclaim, and cleanup timings are candidate operational defaults requiring R09 measurements and operator review before enablement, not proven recovery guarantees. Compatibility upgrade allowlist entries are intentionally empty, not an unspecified permission to compare upgrades. Seven-day freshness, two-observation threshold, and indefinite structured receipt retention are explicit conservative v1 choices for independent review; they still need implementation and operational validation.

An Accepted ADR is deferred until G1 and independent review close, because attempt fencing and cancellation acknowledgement add decisions beyond existing ADRs. No ADR number is reserved. R03 tracker remains untouched in this slice and must not be marked Done from document existence alone.
